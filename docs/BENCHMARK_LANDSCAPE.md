# MEASUREMENT: how to measure a Pluribus reproduction without pros

Researched 2026-10-12. Every claim is tagged by how it was checked:
**[V]** = fetched/read from a primary source today, **[S]** = secondary or search snippet only, **[M]** = from memory / inference, **[?]** = could not verify.

## 1. Direct answer

- **There is no public "near-perfect GTO" 6-max bot you can play, and none can exist in the strict sense.** In 3+ player games a Nash equilibrium is not unique, not a minimax solution, and does not guarantee non-negative results against other equilibria or arbitrary opponents [M, standard theory]. Pluribus itself makes no equilibrium claim; it is "superhuman" by results vs. humans [S: Science 2019 abstract]. GTO Wizard has multiway solvers (3-way postflop, multiway preflop up to 9 players) but they are human-study tools: GTO Wizard's *bot* API is heads-up only [V, below].
- **Best external strength referee: GTO Wizard Benchmark API (HU, 200bb, AIVAT built in, free, key by request).** It is a proprietary strong HU bot that beat Slumbot by 19.4 +/- 4.1 bb/100 [V: arXiv 2603.23660 abstract]. It proves the HU subgame machinery (search, blueprint quality, action translation), not 6-max.
- **Slumbot (HU 200bb, public unauthenticated HTTP, still up today) is the free sanity check.** It is a fixed CFR strategy (ACPC 2018 HU champion); it is weaker than GTO Wizard AI. [V]
- **The only live 6-max arena with an API is Open Poker (openpoker.ai): free, WebSocket JSON, 10/20 blinds, 2-14 week-style seasons, opponents are other developers' bots (incl. template bots like "The Gambler", "Calling Station").** That is a field-of-bots test, not a GTO test; ~96 bots on the board when the earlier attempt played [V docs; S from earlier notes]. Use it for protocol/regression, not strength claims, until you have thousands of hands.
- **For 6-max "how far from equilibrium" the only available quantitative tools are ones you build or borrow:** LBR-style lower-bound exploitability (HU in the paper; no published multiplayer LBR found [V/S]), self-play gauntlets with duplicate + AIVAT, and spot benchmarks (PokerBench: GTO Wizard-labelled 6-max spots).
- **Honest ceiling:** nothing external will tell you "you match Pluribus" at 6-max. The credible claim is: (a) exploitability falls under LBR and HU best-response probes, (b) you beat a graded gauntlet of your own checkpoints and archetypes with AIVAT-corrected confidence intervals, (c) you do not lose to GTO Wizard AI / Slumbot when forced to play HU, (d) you are positive on Open Poker over >=10k hands.

## 3. Recommended measurement stack (priority order)

1. **Internal ground truth (week 1, free, mandatory).** Exact exploitability on Kuhn/Leduc and a toy NLHE (via OpenSpiel `exploitability`/`best_response`, or your own tiny NLHE). Gate: your CFR/MCCFR code converges to the known value. This catches algorithm bugs which no external opponent can.
2. **LBR lower-bound exploitability on your own HU subgame play** (port PokerRL's LBR or write it from the paper: Bayes range tracking, greedy action using `fc` / `fcpa` / pot fractions, check/call elsewhere; average over 2x50,000 duplicate hands). Compare to the paper's table: even ACPC bots show 3,000-5,000 mbb/h lower bounds with fcpa/on-tree LBR, so your target is "lower than those" and "improves monotonically across checkpoints". Treat as regression metric. For 6-max there is no published LBR; the straightforward adaptation (LBR seat vs five frozen copies of your policy, others check/call-style behaviour) gives a best-response *gain against your strategy profile*, which is meaningful for symmetric self-play profiles but is **not** an equilibrium-gap bound [M, my reasoning]. Label it "6-max profile LBR".
3. **Duplicate + AIVAT gauntlet** for 6-max (the Pluribus protocol). Seats rotate on fixed deals; opponents: your earlier checkpoints, fold/call/raise-biased blueprints, heuristic archetypes, trained exploiters. AIVAT multiplayer: Pluribus used AIVAT with a learned/blueprint value function; variance is cut for chance events and for the actions of players whose strategies are known; since the humans' strategies were unknown, correction applied to chance and Pluribus's own decisions; on this basis it reported +48 +/- 25 mbb/game (p=0.028) [S for the numbers; the "only chance + own actions" detail is [M]. Kim & Sandholm (arXiv 2605.14261, 2026) confirm AIVAT's power grows with the number of players whose strategies are known and cite Pluribus as a case where AIVAT revealed superhumanness despite a negative raw result [V]]. In a self-play gauntlet *all* opponent strategies are known, so you get full AIVAT power; implement it. Gate: CI excludes 0 versus each baseline.
4. **GTO Wizard Benchmark API (HU, serious external check).** Steps: request a key at benchmark.gtowizard.com; clone `gtowizard-ai/researcher-api-client`; implement `PokerAgent`. REST flow from OpenAPI: `POST /hands {"game_name":"HUNL 200BB"}` -> game state; `POST /hands/{hand_id}/act`; `GET /hands/in-progress`; `GET /results` (returns `aivat_score`, `total_hands`, std dev); `GET /leaderboard`. Legal action tokens `f`, `c`, `k`, `b` (bet size in chips, same Slumbot-style grammar). Budget up to 100k hands/month; target 20-50k hands for +/-5 bb/100 AIVAT. Your existing `src/slumbot.rs` action parser should adapt with a thin shim. Run your 6-max resolver restricted to 2 players at 200bb (fixed 20,000-chip stacks, 50/100 blinds). Expect to lose at first; the leaderboard ranks by lower bound of the 95% CI.
5. **Slumbot (HU, smoke test + weak external baseline).** Already implemented (`slumbot-live`). Use >=10-20k hands (raw variance is ~100+ bb/100 per 1k hands; the earlier 50-hand run is meaningless). Cost zero. Do the one-hand curl check `curl -i -X POST -d '{}' -H "Content-Type: application/json" https://slumbot.com/slumbot/api/new_hand` first. Be considerate: it is a hobbyist server (no documented rate limit [?]). Compute your own luck adjustment if possible (all-in EV from known hole cards is cheap to implement and cuts variance).
6. **Open Poker (6-max live).** Keep the existing adapter. Rules for interpretation: report trace-filtered bb/100 with CI, require >=10,000 hands for any strength statement, log opponent identities (the hand_result includes seat names) and report win rate per opponent so template "Calling Station" farming does not mask losses to real bots. Use 100bb buy-ins (2,000 chips) for comparability. Seasons reset on a 14-day calendar; compare within one season only. Also note rebuy/score mechanics reward chip count, not bb/100.
7. **PokerBench 6-max spots.** Preflop/postflop action-accuracy and, better, EV-loss if you can reconstruct solutions. Current preflop exact accuracy 77.3% is already above the paper's LLM figures, but the metric rewards pure-strategy guessing: the filter selects spots where one action has >50% frequency, so a deterministic lookup of the modal action scores well while being exploitable. Use as regression, not strength.
8. **HU postflop solver cross-check** (postflop-solver or TexasSolver) on a fixed suite of ~100 HU postflop spots with ranges taken from your blueprint: measure your strategy's exploitability *inside the spot* by plugging it as one side and computing best response with the solver's DCFR (postflop-solver exposes exploitability, `compute_exploitability`, in the Rust API [M]; TexasSolver requires computing it from dumped JSON). AGPL: run as separate processes. Only HU.
9. **Humans** (the paper's real test): out of scope unless recruited.

Anything that is explicitly *not* worth spending time on: LLM-benchmark arenas (PokerBattle, Husky, dev.fun) as strength tests; they test LLM agents against each other and are weak-opponent fields.

## 4. Method notes (LBR, AIVAT, 6-max caveat)

- **LBR (Lisy & Bowling 2017, [V]).** Computes an easily-obtained *lower bound* on exploitability in HUNL by tracking the opponent's range with Bayes' rule and playing a greedy local best response (choose the action with highest value assuming check/call afterwards); the bot's strategy is only queried, so card/betting abstraction and endgame solving are handled. Results (mBB/h, 2x50,000 duplicate hands): Hyperborean 2013/2014 up to ~4,000-5,000; Slumbot 2016 ~3,760-4,020; Act1 ~2,600-3,300; "fold every hand" loses 750 mBB/h, so these bots are all "less exploitable folding" in LBR terms. LBR proves exploitability >= X; it **cannot certify** a bot is unexploitable, and different action sets for LBR (fc, fcpa, 56 bets) give very different bounds. Not extended to 3+ players in any source found [S].
- **AIVAT (Burch et al. 2018, [V]).** Unbiased variance reduction using known strategies of players and chance, plus value-function baselines; ~85% std-dev cut / 44x fewer games in HU man-machine matches. GTO Wizard claims ~10x fewer hands in its benchmark [V]. Kim & Sandholm 2026 (arXiv 2605.14261) analyze heuristic-value pathologies and report up to 43% fewer trials needed on Pluribus gameplay data [V]. Caveat: unbiased only if the value function does not use information that is not allowed; when opponents' strategies are unknown, the correction can only apply to chance + your own actions.
- **6-max equilibrium caveat.** Because 3+-player equilibria are non-unique and not minimax, "match GTO" has no unique referent. Measurement must therefore be relative: results vs a fixed field, and tendency to be exploited (profile LBR), not distance to a single strategy. Pluribus's own claim was "beats elite humans" [S].
